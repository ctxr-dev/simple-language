# Word swaps, full list

Read this when you are editing text for style. The short table in SKILL.md covers the common cases.

The rule is one line: **do not use a longer word just because a shorter one exists.** When the longer word means something the shorter one does not, keep the longer word.

## Words that sound impressive and say nothing

Replace each with the measurable fact behind it.

| Word | What to write instead |
|---|---|
| robust | what it survives: "it retries three times, then dead-letters" |
| seamless | what the user does not have to do: "no restart needed" |
| scalable | the number: "it handles 5k requests per second per pod" |
| performant | the number: "p99 is 40 ms" |
| holistic | say what is included |
| nuanced | write the actual nuance |
| best practice | who says so, and why |
| industry standard | name the standard |
| enterprise-grade | delete it |
| powerful, rich, flexible | name the one feature you mean |
| cutting-edge, state of the art | delete it |
| synergy | say who works with whom, on what |
| game-changer | say what changed |
| actionable | say what someone can actually do |
| best-in-class | delete it |

## Keep these words

Do not swap these. Swapping them makes the text wrong, not simpler.

**Technical terms that mean one exact thing.** Race condition, deadlock, idempotent, eventual consistency, back pressure, memory leak, cold start, cache invalidation, partition, replica, quorum, sharding, migration, rollback, edge case, regression, dependency, transaction, timeout, retry, backoff, throttling. Gloss the term in one sentence if the reader may not know it. Never replace it with a vague phrase.

**Words with an exact technical meaning in context.**

| Word | Keep it when it means |
|---|---|
| implement | writing code against an interface or a spec: "implement `Comparable`" |
| configuration | the config file, object, or values: "the Kafka configuration" |
| utilization | a metric name: "CPU utilization", "disk utilization" |
| optimal | the mathematically best result: "the optimal query plan" |
| terminate | a process or connection ending: "the pod terminated" |
| propagate | a value or error moving through a system: "the error propagates to the caller" |
| aggregate | a real aggregation: "the aggregate function", "an aggregate root" |
| significant | statistical significance |
| execute | running a query, a job, or a binary |
| provision | creating infrastructure |
| deprecate | the formal lifecycle stage |

**Product, protocol, and library names.****Words that look academic but are precise engineering terms.** Do not swap any of these.

| Word | Keep it when it means |
|---|---|
| orthogonal | genuinely independent concerns, changing one does not affect the other |
| canonical | the one official form: a canonical URL, a canonical representation |
| idiomatic | matching a language's normal style: idiomatic Go, idiomatic Rust |
| heuristic | a rule of thumb the code actually applies |
| deterministic | the same input always gives the same output |
| granular, fine-grained | the real size of the unit: per-row locks vs per-table locks |
| caveat | a real exception or limitation you are naming |
| invariant | a condition the code guarantees at all times |
| idempotent | running it twice gives the same result as running it once |
| monotonic | a value that only ever moves one way |
| eventual consistency | the specific replication guarantee, not vague slowness |

 Write them the way their docs write them, including case: PostgreSQL, Kafka, gRPC, OAuth, JWT, Redis, Temporal, Kubernetes, TypeScript.

**Exact quoted text.** Error messages, log lines, stack traces, config keys, and anything the user wrote. Quote it exactly, even when it is badly worded.

## Sentence-level rewrites

Word swaps alone do not fix a heavy sentence. These show the full rewrite.

**Nominalization**

- No: "The implementation of caching resulted in a reduction of database load."
- Yes: "Caching cut the database load."

**Passive voice with a hidden actor**

- No: "The record is locked before the update is applied."
- Yes: "The worker locks the row, then applies the update."

**Buried clause**

- No: "The request, assuming the token has not expired and the rate limit has not been reached, is forwarded to the upstream service."
- Yes: "If the token is valid and the rate limit is not hit, the request goes to the upstream service."

**Stacked hedges**

- No: "It is possible that this could potentially lead to some degree of data inconsistency in certain edge cases."
- Yes: "This can leave the two tables out of sync. It needs two writes to fail in a specific order, so it is rare."

**Abstraction climbing**

- No: "The service interacts with the persistence layer through a data access abstraction."
- Yes: "The service reads and writes Postgres through the repository classes."

**Vague instead of precise**

- No: "There are performance concerns with this approach at scale."
- Yes: "This runs one query per row. At 10,000 rows that is 10,000 round trips, so the endpoint takes about 40 seconds."
